    How it works

    1. Paste logs exactly as the manager receives them, syslog header included. The header decides which decoders Wazuh even tries.
    2. Review fields. Untick what you do not need and rename. For free-form logs, click tokens to turn them into fields.
    3. Verify. Every change re-runs an emulation of wazuh-analysisd over all your lines: pre-decoding, program_name routing, siblings, offsets and the JSON plugin.
    4. Deploy. Save the decoder to /var/ossec/etc/decoders/, restart the manager and confirm with wazuh-logtest.

    Why the output looks the way it does

    • Two parents with the same name: one with <program_name>, one with <prematch>. Events carrying a syslog program name are only matched against decoders that declare one.
    • The parent prematch is anchored on the earliest stable fields of the line, so other sources are rejected on their first characters.
    • One sibling child per field: Wazuh runs every sibling, so a missing field never breaks the others.
    • PCRE2 without raw < (written \x3c): Wazuh's XML reader does not decode entities.
    • Plain JSON is claimed by Wazuh's built-in json decoder, so you get rules for it instead of a decoder that would never run.
